# 1. Требования к платформе InternHub

Документ фиксирует, **что** должна делать система и **с какими характеристиками**. Он служит основой для главы 2 пояснительной записки и чек-листом приёмки: каждое требование имеет номер, на который ссылаются задачи и тесты.

Приоритеты: **M** — обязательно для MVP (этапы 1–4), **S** — желательно (этап 5), **C** — исследовательская часть (этап 6).

## 1.1 Роли

| Роль              | Кто это                     | Как появляется                                        |
| ----------------- | --------------------------- | ----------------------------------------------------- |
| Гость             | неавторизованный посетитель | —                                                     |
| Студент           | обучающийся вуза            | регистрация, подтверждение почты                      |
| Работодатель      | представитель организации   | регистрация + верификация организации администратором |
| Администратор     | сотрудник вуза / платформы  | назначается вручную, выбрать при регистрации нельзя   |
| Преподаватель (S) | куратор практики            | назначается администратором (этап 5)                  |

## 1.2 Функциональные требования

### Учётные записи и доступ

| №   | Требование                                                                 | Приоритет |
| --- | -------------------------------------------------------------------------- | --------- |
| F-1 | Регистрация студента: имя, фамилия, группа, курс, email, пароль            | M         |
| F-2 | Регистрация работодателя с созданием организации (название, ИНН, ОГРН)     | M         |
| F-3 | Подтверждение email по ссылке из письма; без подтверждения вход невозможен | M         |
| F-4 | Вход по email и паролю, выход, восстановление пароля                       | M         |
| F-5 | Роль назначается сервером; пользователь не может изменить свою роль        | M         |
| F-6 | Верификация организации администратором (VERIFIED / REJECTED / BLOCKED)    | M         |

### Задания

| №    | Требование                                                                                                                                                                                                          | Приоритет |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| F-10 | Работодатель верифицированной организации создаёт задание: название, описание, ожидаемый результат, критерии оценки, сложность, срок, теги, лимит участников, условия использования результата, архив с материалами | M         |
| F-11 | Задание проходит модерацию: администратор публикует его или возвращает автору с комментарием                                                                                                                        | M         |
| F-12 | Автор редактирует черновик и возвращённое задание; изменение опубликованного снова отправляет его на модерацию                                                                                                      | M         |
| F-13 | Автор закрывает приём решений или удаляет задание (задание с решениями — только в архив)                                                                                                                            | M         |
| F-14 | Лента опубликованных заданий с фильтрами по сложности, организации и тегам, с постраничной подгрузкой                                                                                                               | M         |
| F-15 | Страница задания: полное описание, материалы, таблица активности (студент, статус, дата)                                                                                                                            | M         |
| F-16 | Вся история смены статусов задания сохраняется (кто, когда, комментарий)                                                                                                                                            | M         |

### Участие и решения

| №    | Требование                                                                                                                               | Приоритет |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| F-20 | Студент добавляет задания в избранное; число отслеживающих видно на карточке                                                             | M         |
| F-21 | Студент подаёт заявку на выполнение; работодатель принимает или отклоняет её                                                             | M         |
| F-22 | По принятой заявке студент сдаёт решение: ссылка на репозиторий (обязательна, если так требует задание), комментарий, архив, изображения | M         |
| F-23 | Работодатель проверяет решение: принять (с оценкой 1–5), вернуть на доработку, отклонить — с комментарием                                | M         |
| F-24 | После доработки студент отправляет решение повторно; история статусов сохраняется                                                        | M         |
| F-25 | Принятые решения образуют портфолио студента с учётом условий использования результата                                                   | M         |

## 1.3 Нефункциональные требования

| №    | Характеристика                                   | Значение                                                                         |
| ---- | ------------------------------------------------ | -------------------------------------------------------------------------------- |
| N-1  | Время ответа страницы ленты заданий (сервер)     | ≤ 500 мс для 95 % запросов при 10 000 заданий                                    |
| N-2  | Время до отображения первой страницы (LCP) на 4G | ≤ 2,5 с                                                                          |
| N-3  | Одновременные пользователи                       | не менее 200 без деградации N-1                                                  |
| N-4  | Доступность                                      | 99 % в месяц (виртуальный сервер, без резервирования)                            |
| N-5  | Максимальный размер файла                        | 50 МБ; архивы: zip, rar, 7z, tar, gz; изображения: png, jpg, webp                |
| N-6  | Браузеры                                         | две последние версии Chrome, Edge, Firefox, Safari, Яндекс Браузер               |
| N-7  | Адаптивность                                     | от 360 px по ширине                                                              |
| N-8  | Доступность интерфейса                           | управление с клавиатуры, подписи у полей, контраст по WCAG 2.1 AA                |
| N-9  | Языки интерфейса                                 | русский (основной), английский                                                   |
| N-10 | Резервное копирование БД                         | ежедневно, хранение 14 дней; проверка восстановления раз в месяц                 |
| N-11 | Хранение данных                                  | история статусов — бессрочно; удалённый аккаунт обезличивается в течение 30 дней |

## 1.4 Требования безопасности

| №   | Требование                                                                                               |
| --- | -------------------------------------------------------------------------------------------------------- |
| S-1 | Пароли хранятся только в виде хэша (scrypt/bcrypt); открытый пароль нигде не сохраняется и не логируется |
| S-2 | Сессия — в httpOnly-куке с флагами Secure и SameSite=Lax; срок жизни ограничен                           |
| S-3 | Каждое изменяющее действие проверяет на сервере: кто пользователь, его роль, владеет ли он объектом      |
| S-4 | Все входные данные проверяются на сервере (zod), даже если уже проверены на клиенте                      |
| S-5 | Файлы хранятся в приватном хранилище; скачивание — по временной ссылке после проверки прав               |
| S-6 | Тип и размер файла проверяются на сервере; имя файла в хранилище генерируется сервером                   |
| S-7 | Персональные данные студентов хранятся на серверах в РФ (152-ФЗ)                                         |
| S-8 | Ограничение частоты запросов на вход и регистрацию                                                       |
| S-9 | Учёт угроз OWASP ASVS уровня 1                                                                           |

## 1.5 Сценарии использования

**Студент:** зарегистрироваться → подтвердить почту → найти задание (фильтры) → добавить в избранное → подать заявку → получить подтверждение → сдать решение → получить обратную связь → при необходимости доработать → решение принято и появилось в портфолио.

**Работодатель:** зарегистрировать организацию → дождаться верификации → создать задание → отправить на модерацию → получить уведомление о публикации → принять заявки → проверить решения → принять / вернуть на доработку / отклонить → получать еженедельный отчёт.

**Администратор:** проверить организацию (ИНН, ОГРН, сайт) → модерировать задания → реагировать на жалобы → управлять справочником тегов.

**Преподаватель (этап 5):** создать практику → добавить группу → выбрать задания → контролировать выполнение → подтвердить результат → выгрузить отчёт.
